# 问题与解决记录

本文记录字幕流水线最近修过的关键问题、根因、解决方式和使用注意。

## 1. 选择远程服务器翻译时，本地 GPU 仍然满载

### 现象

前端已经连接远程 Ollama，并在下拉框中选择了远程模型，但本机 `nvidia-smi` 仍显示本地 `llama-server.exe` 在跑，`ollama ps` 也显示本地 `qwen3:14b` 常驻 GPU。

### 根因

最初有两个独立原因：

- 前端下拉框有远程模型选项，但启动任务时没有把 `llmModel` 写入请求 payload。后端拿不到 `llm_model` 后回退到默认 `qwen3:14b`，于是请求仍打到本机 `http://localhost:11434`。
- 音频识别和远程翻译在同一个 Python 子进程内串行执行。faster-whisper 的 `large-v3` 完成识别后只离开了局部变量作用域，没有显式调用底层 CTranslate2 Whisper 的 `unload_model()`；进入远程 Qwen 阶段时，本地 CUDA 模型仍可能保留显存。

另外，`ollama ps` 中的 `100% GPU` 表示模型完全驻留在 GPU，并不等于瞬时算力占用。真正是否在计算要看 `nvidia-smi` 的 GPU-Util 或 `nvidia-smi pmon`。

### 修复

- 前端 payload 增加 `llm_model`。
- 片名分析也使用当前选择的模型。
- 远程模型列表刷新后恢复用户保存的远程模型选择。
- `remote:<name>:<model>` 会被后端路由到当前网页实例拥有的 SSH 隧道，再转发到远程 `11434`；首选本地端口是 `11435`，被占用时使用动态空闲端口。
- faster-whisper 识别生成器消费完成后在 `finally` 中调用 CTranslate2 `unload_model()`；识别异常时也会执行释放。官方 API说明该方法会卸载 Whisper 模型并保留最小运行时上下文。
- Ollama 模型默认只驻留到最后一次请求后 10 分钟，不再用 `keep_alive=-1` 永久占用本地或远端显存。

### 使用注意

如果只想释放本地 Ollama 显存，可以运行：

```powershell
ollama stop qwen3:14b
```

如果本地进程仍出现在 `nvidia-smi` 但显存已从数 GB 降到很小，这是 CUDA 运行时上下文，不代表 Whisper 权重仍在 GPU。要完全移除该进程只能让当前字幕任务进程结束。

## 2. 中断后 checkpoint 可能损坏

### 现象

任务被终止时，`*.segments.checkpoint.json` 或其它 JSON 缓存偶尔只写了一半，之后前端状态或继续运行读 JSON 会失败。

### 根因

旧代码直接 `write_text(json.dumps(...))` 写目标文件。进程在写入中间被杀掉时，目标文件会留下半截 JSON。

### 修复

JSON 缓存改成原子写：

1. 先写同目录临时文件。
2. 写完后用 replace 替换目标文件。

覆盖范围包括：

- `*.segments.source.json`
- `*.segments.checkpoint.json`
- OCR cache
- image events cache
- Ollama translation cache

## 3. Whisper/ASR 产生重复字幕，翻译阶段无法修复

### 现象

音频识别出的字幕有连续重复或重叠片段，例如同一句话被识别成多条相似字幕，前端 checkpoint 预览和最终 ASS 都会重复显示。

### 根因

重复已经存在于 ASR 之后的 `segments.source.json`。旧翻译提示词又明确要求：

- 每个输入行必须对应一个输出对象。
- 不允许合并。
- 不允许省略。

这导致即使用更强的 `qwen3:30b`，模型也只能逐条翻译重复内容，不能真正清洗结构。

### 修复

翻译阶段仍保持“一条输入一条 JSON 输出”用于 checkpoint 对齐，但只允许模型返回文本和显示控制：

```json
{
  "index": 0,
  "corrected_text": "complete sentence",
  "chinese_translation": "完整译文",
  "display": true
}
```

规则变为：

- 重复或重叠的 ASR 片段可以设置为 `"display": false`。
- 模型不能返回或修改时间；提示词明确要求优先保留最早的完整片段，只隐藏后续重复片段。
- 程序根据被隐藏片段确定性地延长上一条字幕，最长不超过 6 秒。
- checkpoint 仍保留所有原始片段，保证续跑能校验原始时间轴。
- 生成 ASS 时只输出 `display != false` 的片段。
- 前端 checkpoint 预览也只显示可见片段。

旧 checkpoint 没有 `display` 元数据，会被自动忽略并重新翻译。包含旧 `display_start/display_end` 的 checkpoint 会在续跑时删除模型时间并从源时间锚重建显示区间。

## 4. “从中断处继续”仍然重新抽取音频和 Whisper 识别

### 现象

指定输出目录里已经有：

```text
<片名>.segments.source.json
<片名>.segments.checkpoint.json
```

但点击“从中断处继续”后，程序仍然重新抽取 `.wav` 并重新跑 faster-whisper。

### 根因

前端的“从中断处继续”只是不删除缓存文件；但 `audio_to_subtitle.py` 主流程没有读取已有 `*.segments.source.json` 的逻辑。它每次都会重新走来源选择：

1. sidecar
2. embedded
3. audio extraction
4. Whisper transcription

然后再覆盖写入 `segments.source.json`。

### 修复

主流程现在会优先读取：

```text
<输出目录>\<片名>.segments.source.json
```

只要这个缓存存在且可读，就直接复用已切分好的源字幕事件，不再抽取音频、不再跑 Whisper。

只有以下情况才会重新抽取/识别：

- 用户选择“从头开始”，前端会先删除 `segments.source.json`。
- `segments.source.json` 不存在。
- `segments.source.json` 损坏或结构不合法。
- 旧双语合并缓存缺少新版时间锚版本；这类缓存只重建字幕配对并继续复用 embedded/OCR 中间缓存。

这次修复还增加了测试，确保已有 source cache 时 `extract_audio()` 和 `transcribe_audio()` 不会被调用。

## 5. “从中断处继续”和“从头开始”的边界

### 从中断处继续

保留：

- `*.segments.source.json`
- `*.segments.checkpoint.json`
- 已有输出 ASS
- embedded/OCR cache

行为：

- 优先复用 source cache，跳过抽取/识别。
- 如果 checkpoint 与当前 source cache 匹配，并且包含新格式 `display` 元数据，则继续翻译。
- 如果 checkpoint 是旧格式或损坏，则重新翻译，但仍不重新抽取音频或跑 Whisper。

### 从头开始

前端会删除：

- `*.segments.source.json`
- `*.segments.checkpoint.json`
- `*.en.ass`
- `*.zh.ass`
- `*.bilingual.ass`
- `embedded/`
- 同名临时 `.wav`

行为：

- 重新分析来源。
- 必要时重新抽取音频和 Whisper 识别。
- 重新 OCR 或重新翻译。

## 7. 已有中文字幕时不应重新翻译

### 现象

电影目录或视频内已经带有中文字幕时，旧流程仍可能选择英文字幕、内嵌字幕或音频识别结果，然后继续执行英译中。这样会浪费远程模型时间，也可能把原本较好的官方中文字幕改坏。

### 根因

旧的 `audio_to_subtitle.py` 源选择逻辑一次只选一个字幕来源：

1. 找到一个 sidecar 字幕就直接解析。
2. 没找到再尝试内嵌字幕。
3. 再失败才抽音频并跑 Whisper。

它没有先判断“是否已经存在中文字幕”，也没有把英文字幕和中文字幕按时间轴合并成双语源。因此即使目录里同时有 `*.en.srt` 和 `*.zh.srt`，也可能进入翻译路径。

### 修复

- 源选择阶段先扫描同目录 sidecar 字幕，识别中文和英文字幕。
- sidecar 未命中时，再扫描内嵌字幕流，优先选择中文流，并可同时选择英文流作为参考。
- 前端提供“中英字幕合并”开关，并分别提供中文字幕文件/英文字幕文件、内封中文字幕轨/内封英文字幕轨选择。
- 英文和中文字幕按时间重叠配对合并为统一的 source cache；有英文时以英文对白轨为时间锚，不再取两个轨道时间范围的并集。
- 两条字幕没有重叠且间隔超过 0.75 秒时不再强行配对。
- 中文字幕统一繁体转简体。
- 已经存在中文时跳过翻译，改走“双语校对”：
  - 英文也会校对，因为它可能来自 OCR。
  - 中文会校对 OCR/字幕识别错误，并保持简体中文。
  - 中文原文非空且完整时只校对，不重新翻译。
  - 中文为空，或英文里有音乐、掌声、说话人标签等 SDH 信息而中文缺失时，才从英文补翻缺失部分。
  - 人名和重复术语会要求在上下文中保持一致，避免同一个名字一会翻译一会不翻译。
  - 重复、重叠、碎片行仍可通过 `display=false` 隐藏，保留 checkpoint 可续跑。

## 8. 远程服务器密码保存

### 现象

远程服务器连接信息可以保存主机、端口、用户名和显示名称，但每次重新打开页面都要重新输入密码。

### 修复

远程连接弹窗增加“保存密码到本机浏览器”选项。勾选后，密码会和远程服务器配置一起保存到当前浏览器的 `localStorage`，下次打开弹窗会自动填入。

### 注意

该密码保存是本机浏览器明文保存，方便个人本机使用；如果是共享电脑，不要勾选保存密码。

## 9. 网页端选项过多且没有层级

### 现象

无论选择已有字幕、内封字幕还是 Whisper 音频识别，页面都会同时显示：

- 已有字幕文件；
- 内封中英文字幕轨；
- 音频轨；
- ASR 与 OCR 语言；
- 批量、上下文和字幕显示限制。

桌面端难以扫描，移动端首屏会被大量无关控件拉长；隐藏来源的旧选择还可能被一起提交到后端。

### 根因

前端只有一张平铺表单，没有“用户选择的来源”和“当前分析结果决定的自动来源”这两个状态层。`payload()` 也无条件读取所有字段。

### 修复

- `auto` 模式在分析前只显示通用选项；分析完成后只展开自动命中的来源。
- `sidecar`/`embedded` 只显示已有字幕设置；`audio` 只显示音频轨和 ASR 语言。
- 勾选中英合并时显示中英文两个选择器；取消勾选后只显示单字幕选择器。
- OCR 语言只在内封字幕路径显示。
- 批量、上下文、最大词数、最大字符和最长秒数收进“高级设置”。
- `payload()` 只提交当前来源有效的选择器值，防止隐藏旧值污染命令参数。

## 10. 对白结束后字幕才出现，且单条字幕过长

### 现象

使用已有内封字幕生成结果后，部分字幕在对白结束后才出现，部分双语字幕过长。对真实 `Oppenheimer` 输出的检查发现：

- 126 条 checkpoint 字幕的显示结束时间被向后移动超过 1 秒；
- 最严重的一条整体向后移动约 25 秒；
- 最长显示时间为 10.64 秒；
- 模型把最长文本从源数据的 83 字符扩写到 116 字符。

### 根因

问题由四条路径叠加：

1. 模型可以自由输出 `display_start/display_end`，程序只检查是否落在几十条上下文的大窗口内。
2. 隐藏连续重复片段时，上一条字幕可被无限延长。
3. 已有字幕和旧 source cache 绕过统一断句。
4. 断句只发生在调用模型前；模型校对或补翻后扩写的文本不会再次检查长度。

### 修复

- 禁止模型修改时间；只接受文本和 `display`。
- 旧 checkpoint 的模型时间在加载时清除，并从源时间锚重建。
- 重复片段造成的显示延长限制在 6 秒内。
- 已有字幕、音频识别、内封 OCR 和 source cache 全部进入同一套源断句。
- ASS 生成前再次处理模型输出，确保扩写后的中英文仍满足显示限制。
- 默认限制改为 12 个英文词、56 个英文字符、28 个中文字符、5.5 秒。

同一真实样本离线重算后：

| 指标 | 修复前 checkpoint | 修复后渲染数据 |
| --- | ---: | ---: |
| 最长显示时间 | 10.64 秒 | 5.46 秒 |
| 超过 5.5 秒 | 50 | 0 |
| 最长文本 | 116 字符 | 56 字符 |
| 超过 56 字符 | 517 | 0 |

## 11. 旧双语 source cache 的兼容边界

旧的纯 ASR/单语 source cache 仍可直接复用，不会重新抽取音频或运行 Whisper。

旧的“已有中英字幕合并”source cache 没有记录新的英文时间锚策略，无法从合并结果反推出原始两条轨道的准确时间。因此程序会只对这类旧缓存执行一次重建：

- sidecar 字幕会重新解析原字幕文件；
- 内封字幕会重新走配对；带输入指纹的新版 embedded/OCR 中间缓存可复用；
- 新 source cache 写入 `source_cache_version: 2`，后续继续运行时正常复用。

旧 OCR 缓存只记录识别结果条数，无法证明其对应当前图片、OCR 语言和精度模式，因此升级后会失效并重建一次。新版缓存可以从已完成图片继续，不会每次都从第 1 张开始。

## 12. 临时 WAV 可能覆盖或删除用户文件

### 现象与根因

旧流程把临时音频固定写到视频旁边的同名 `.wav`。任务退出和网页“从头开始”都会无条件删除这个路径，因此可能覆盖并删除用户原本就存在的同名 WAV；只读电影目录也可能导致抽取失败。

### 修复

- 临时音频改写到当前字幕输出目录，文件名包含 `.subtitle-audio.<PID>.wav`。
- 正常退出只删除本进程创建的临时文件。
- “从头开始”只清理输出目录内符合流水线专用命名的残留文件，不再触碰视频旁边的 WAV。

## 13. 同一影片可以重复启动任务

### 现象与根因

连续点击“运行程序”可启动多个进程。它们会同时写同一个 source cache、checkpoint、ASS 和日志，造成进度覆盖或文件竞争。

### 修复

- 后端使用进程注册锁检查同一系列名和片名的活动任务；已运行时拒绝第二次启动并返回现有 PID。
- 前端提交后立即禁用“运行程序”，运行期间只启用“终止运行”。
- 状态读取和停止操作使用同一注册锁读取进程表，避免并发修改。

## 14. 只选英文内封字幕时可能忽略用户选择

开启双轨合并但影片没有可用中文字幕时，旧回退路径只读取通用 `subtitle_stream`，会忽略用户在“内封英文字幕轨”中明确选定的轨道。

现在普通内封字幕回退顺序为：

1. 通用内封字幕轨；
2. 已选英文字幕轨；
3. 已选中文字幕轨。

同样，只有显式英文 sidecar 时会把它作为单字幕翻译来源，不再退回不确定的自动文件。

## 15. 更换字幕文件或轨道后仍复用旧 source cache

### 现象与根因

旧缓存只比较源语言，没有记录它来自哪个视频、sidecar 文件、内封轨、音频轨或 OCR 配置。因此同一个系列名和片名下更换字幕选择后，程序仍可能直接加载上一轮 source cache；checkpoint 的开头时间和文本刚好相同时，也可能继续复用旧校对结果。

### 修复

- source cache 写入 `source_request_fingerprint`，指纹覆盖视频文件、字幕文件大小及修改时间、来源模式、中英合并开关、字幕/音频轨、源语言、ASR 语言和 OCR 配置。
- 当前请求与指纹不一致时重建 source，不再继续使用旧选择。
- checkpoint 同时校验来源指纹。
- 旧纯 ASR 缓存继续允许续跑；一次成功完成后，source cache 和 checkpoint 会一起升级指纹，不需要重新抽取音频或运行 Whisper。

## 16. 模型缺行或空译文会污染 checkpoint

### 现象与根因

旧逻辑只要求模型返回 JSON 列表。模型少返回一条、重复 `index`、返回可见空中文或连续语言校验失败时，程序可能用原外文兜底，并把该批次写成“已完成”。后续续跑不会再修复这些行。

### 修复

- 每个批次必须返回恰好相同数量的对象，并完整覆盖 `0..N-1`，不允许缺失、越界或重复索引。
- 可见字幕必须有有效源文和中文；隐藏的重复行允许为空。
- 批次响应或单句重试连续失败时抛出错误，中断前不写当前批次。
- 最近一个完整 checkpoint 保持不变，恢复模型服务后可从该位置继续。
- 已经完整完成的最后一个不足整批 checkpoint 不再因批大小取整而被重复处理。

## 17. 前端重启后忘记正在运行的任务

### 现象与根因

任务注册表只存在于 `subtitle_frontend.py` 内存中。关闭或重启网页服务后，翻译子进程仍在运行，但新前端认为任务不存在，会重新启用“运行程序”，也无法终止原进程。

### 修复

- 每个前端任务在输出目录写入专用 `.subtitle-run.json`，记录 PID、进程创建时间、精确命令、输出目录和日志。
- 恢复任务时使用 `psutil` 核对 PID 创建时间、脚本路径、系列名和片名，防止 PID 被其他进程复用。
- 状态查询、重复启动检查和终止操作都可从该文件恢复任务。
- 子进程正常或异常退出时清理状态文件；强制终止和发现陈旧状态时也会清理。

## 18. 8765 被其他项目占用时打开错误网页

旧 `start_frontend.bat` 只要发现 `http://127.0.0.1:8765/` 能访问，就认为字幕前端已经启动。其他本地项目占用该端口时，会直接打开无关页面，让最新前端修改看起来没有生效。

现在前端提供 `/api/health` 身份响应，启动脚本必须确认 `app=bilingual-subtitle-pipeline` 才复用现有服务；否则自动寻找 `8766..8775` 的空闲端口。

## 19. 自动模式可能选到同目录其他剧集的字幕

### 现象与根因

目录中存在多集视频和字幕时，旧逻辑会把任意 `.srt/.ass/.vtt` 都视为可用 sidecar。当当前视频没有同名字幕时，排序结果仍可能选中另一集的英文或中文字幕。

### 修复

- 自动选择只接受字幕文件名与当前视频 stem 相同或互相包含的候选。
- 如果目录里只有一个字幕文件，仍允许作为兼容回退。
- 多个候选都不匹配时，前端继续列出它们供用户手动选择，但 `auto` 不会擅自采用。

## 20. 人名和术语在跨批次翻译中不一致

提示词过去只提供前后源字幕，不包含前一批已经确认的中文译文。因此模型虽然看到同一个英文名字，却看不到之前采用的是音译、意译还是保留原名。

现在每个后续批次额外收到“PREVIOUS APPROVED OUTPUT”，包含最近已确认的源文和中文。该上下文只用于匹配人名与术语，不作为目标行输出；从 checkpoint 续跑时也会使用已完成结果。

## 21. OCR 缓存条数相同但内容可能属于旧视频或旧配置

### 现象与根因

旧 PGS/OCR 缓存只检查 JSON 条数是否等于当前图片条数。不同视频、不同字幕轨或不同 OCR 配置恰好产生相同数量的图片时，会直接复用旧文字；OCR 中断后也会从第 1 张重新开始。

抽取出的 `.srt` 和 `.sup` 同样只按文件是否存在复用，没有记录原视频、轨道和编码，输出目录复用时可能读到旧中间产物。

### 修复

- `.srt/.sup` 抽取结果增加元数据，绑定原视频绝对路径、文件大小、修改时间、字幕轨索引和输出编码。
- PGS 图片缓存绑定 SUP 文件身份、缩放比例、裁剪边距和测试条数，并确认所有图片文件仍然存在。
- OCR cache 升级为版本化对象，绑定 OCR 语言、设备、精度模式以及每张图片的时间和哈希。
- OCR 每 20 张原子写入部分结果；配置和图片指纹完整匹配时从下一张继续。
- OCR 完成后输出有效文字数量；所有图片都为空时直接报错，提示检查 OCR 语言和字幕轨。

兼容边界：旧的列表式 OCR cache 因缺少上述指纹会重新 OCR 一次；新版 cache 后续可以安全复用或续跑。

## 22. 中英文字幕存在一对多或多对一时合并错误

### 现象与根因

两条字幕轨的断句通常不同，例如两条短英文对应一条中文，或一条英文对应两条中文。旧算法逐条贪心且每条中文只能使用一次，因此第一条匹配后，剩余内容会变成单语字幕，造成重复、缺失或过长。

### 修复

- 对英文 SDH/音乐提示继续保留英文单条，交给后续规则在中文缺失时补译。
- 普通对白按“至少覆盖较短事件 50%”建立强重叠关系，把真实的一对多、多对一事件合成同一个双语单元。
- 合并时按时间顺序拼接文字并消除相邻完全重复文本；中文不额外插入空格。
- 普通相邻字幕只有轻微轨道偏移时不会被连锁合并。
- 没有强重叠的剩余事件继续使用原来的近邻匹配；间隔超过 0.75 秒仍不强配。

合成后仍进入统一的断句和显示时长限制，因此不会因为配对分组重新产生超长显示。

## 23. 翻译失败后网页错误显示“未运行”

### 现象与根因

子进程异常退出后，前端会从活动进程表删除任务，但旧状态只有 `running` 布尔值。只要进程不再运行，页面就退回“未运行”，用户看不到失败发生在哪一阶段，也不知道 checkpoint 是否真的存在。

### 修复

- 状态接口区分 `running / success / failed / interrupted / stopped / idle`。
- 失败时保留最后活动阶段、退出码和 stderr 最后一条错误摘要。
- 页面显示红色失败阶段和可操作提示；只有 `checkpoint_exists=true` 才提示“从中断继续”，没有 checkpoint 时明确要求检查日志后重新运行。
- 用户主动终止会在日志写入专用标记，刷新网页后仍显示“已终止”，不会被旧 stderr 误判为失败。
- 待执行阶段改为中性灰色，不再全部显示成红色，红色只表示真实失败。

浏览器验证覆盖了来源选项层级、失败阶段、无 checkpoint 提示和有 checkpoint 恢复提示。

## 24. 项目迁移后旧任务无法发现，继续运行重新抽音频并识别

### 现象与根因

项目移动到 `E:\6_Engineering_Projects\bilingual-subtitle-pipeline` 后，前端和命令行仍通过“项目目录的上一级”推导默认输出根目录，结果变成不存在的 `E:\6_Engineering_Projects\1 字幕`。网页还会把这个旧值保存在 `localStorage`。

旧任务实际仍在影片附近，但程序根据错误根目录找不到 `.segments.source.json` 和 `.segments.checkpoint.json`，于是把“从中断继续”当成新任务，重新进入音频抽取和 Whisper。

### 修复

- 新增共享输出目录解析器，前端和命令行使用同一套规则。
- 优先检查用户手动指定的目录；空白或旧项目默认值则自动查找。
- 在视频目录及其近邻 `1 字幕` 目录中，先按系列名/片名精确查找 source cache、checkpoint 或双语 ASS。
- 精确名称不一致时，按清洗后的片名相似度查找；剧集必须同时满足 `SxxExx`、`4of8` 或 `Episode 4` 等集号身份，避免串到其他集。
- 找到旧任务后继续使用原输出根目录；找不到才建议 `<视频所在目录>\1 字幕`。
- 前端输出目录默认留空，并清除浏览器里遗留的 `E:\6_Engineering_Projects\1 字幕`。显式配置 `SUBTITLE_OUTPUT_ROOT` 时不执行该清理。

真实第 4 集只读验证结果：

| 项目 | 结果 |
| --- | --- |
| 恢复的输出根目录 | `E:\4杜比HDR\电影\21世纪性爱指南` |
| source cache | 682 条，存在 |
| checkpoint | 682 条，存在 |
| 可见 checkpoint | 407 条 |
| 状态接口 | `success` |

兼容边界：旧纯 ASR source cache 可以直接复用，不会重新抽取音频或运行 Whisper。本轮切分规则改变后，旧 checkpoint 可能与新分段不匹配，需要基于现有 source cache 重新运行一次 Qwen 校对翻译。

## 25. 词级断句仍会超过最大字符数或最长秒数

### 现象与根因

旧的词级断句循环先把下一个词加入当前字幕，再检查词数、字符数和时长。触发限制时，已经越界的词仍留在当前块中，因此设置 56 字符和 5.5 秒后仍可能得到更长字幕。

单个 Whisper 词本身带有异常长时间戳时，也无法再通过词边界继续拆分。

### 修复

- 加入下一个词前先构造候选块并检查限制；候选越界时先结束当前块，再用该词开启下一块。
- 最终 ASS 准备阶段再次执行时长兜底，单个异常长词也不会突破配置上限。
- 字符数、词数和时长限制同时生效，模型校对或补译后的文本也会再次切分。

真实第 4 集的 682 条 source cache 只读离线复算结果：

| 指标 | 修复后 |
| --- | ---: |
| 显示单元 | 819 |
| 最长显示时间 | 5.50 秒 |
| 超过 5.5 秒 | 0 |
| 最长源文 | 56 字符 |
| 超过 56 字符 | 0 |

旧 checkpoint 中 407 条可见项经过最终输出准备后得到 727 个显示单元，最长 5.44 秒，英文最长 56 字符，中文最长 24 字符。

## 26. Qwen 已处理后仍可能残留连续完全重复字幕

### 现象与根因

Qwen 会结合上下文隐藏 ASR 滚动重复和幻觉重复，但模型输出不是确定性规则。网络重试、批次边界或上下文判断差异仍可能让少量完全相同的长句连续显示。

### 修复

- 在生成 ASS 前增加确定性重复过滤，作为模型判断后的最后防线。
- 只处理标准化后完全相同且足够长的文本，并要求与上一次同文字幕间隔不超过 4 秒。
- 被隐藏项可在受限范围内延长上一条字幕，但总显示时间仍受最长秒数限制。
- `No.`、`Yes.` 等短对白重复不会被自动隐藏。
- 间隔较远的相同台词不会被自动隐藏，避免删除剧情中的真实复述。

## 27. 固定 ASS 分辨率和字号导致不同画幅、手机播放效果不一致

### 现象与根因

新旧两条 ASS 生成路径各自维护一套样式，并固定使用 `PlayResX: 1920`、`PlayResY: 1080` 和 Windows 字体。宽屏、老式 TVRip、非方形像素视频或旋转视频仍被当成标准 16:9 处理，水平安全边距和换行宽度会失真；英文单独出现时还可能沿用双语第二行的较小字号。

字体文件只提供字形，不包含“按手机屏幕自动调整字号”的能力。外置 ASS 只保存字体族名，目标设备没有同名字体时会回退；部分手机播放器还会覆盖或忽略 ASS 样式。

### 修复

- 新增共享 ASS 样式模块，新旧生成器统一使用 `Chinese`、`Source` 和 `SourceOnly` 角色样式。
- 用 `ffprobe` 读取视频宽高、SAR、DAR 和旋转信息，以固定 `PlayResY: 1080` 和真实显示宽高比计算 `PlayResX`。
- 增加 `adaptive`、`mobile`、`compact` 三种显示方案，以及 70% 到 160% 的字号比例。
- 水平边距按画面宽度百分比计算；字号、底部边距、描边和阴影按统一虚拟画面缩放。
- 中英双语明确使用中文主行和较小英文参考行；只有英文的 SDH/音乐提示使用 `SourceOnly`，不再产生空白中文行。
- 前端把外观控制收进独立折叠层，默认界面不会继续平铺选项。
- 字体族名会清理 ASS CSV 中非法的逗号和换行，避免破坏样式表。

真实第 4 集验证：

| 项目 | 结果 |
| --- | --- |
| 源视频 | `640×352`，SAR `1:1`，DAR `20:11` |
| 旧 ASS 坐标系 | `1920×1080` |
| 新 ASS 坐标系 | `1964×1080` |
| 自适应字号 | 中文 52，英文 38 |
| 手机大字字号 | 中文 60，英文 43 |
| 回归测试 | 84 项通过 |

## 28. 手机字幕“自适应”的兼容边界与后续质量项

### 已明确的边界

- 生成器只知道视频画面几何信息，不知道手机的物理尺寸、观看距离、刘海/系统控件、播放时横竖屏状态或系统无障碍字号。
- ASS 字号按脚本分辨率随视频画面缩放，不等同于 iOS Dynamic Type 或 Android 系统字幕字号。
- 外置 ASS 不会自动携带字体文件。跨设备使用自定义字体时，应把字体作为 MKV 附件封装，并确保 ASS 使用字体内部 family name。
- 不同手机播放器对 ASS、内嵌字体、样式覆盖和碰撞处理的支持并不一致；播放器强制改字体、字号或去除样式后，最终效果不再由本项目控制。
- “手机大字”是显式的大字号预设，不是对所有设备和方向都能自动选中的运行时布局。

### 仍需继续评估的字幕质量项

- 每秒字符数和语言行宽目标已在问题 29 中补充；字体指标/Unicode 估算的像素宽度自动拆句已在问题 46 完成，目标播放器的实际字体回退仍需实机验证。
- 系统尚未检测画面底部人脸、片内硬字幕、UI 或关键构图，不能自动把字幕临时移到顶部。
- 镜头切换点微调已在问题 51 完成；源字幕整体/分段漂移的音频对齐见问题 36。
- 自定义字体的小型 Matroska 字幕包已在问题 39 完成；整片 MKV 重封装仍保持显式分发步骤。
- HDR、极亮/极暗镜头和色觉无障碍只通过白字、黑描边提供基础可读性，尚无逐镜头对比度分析。
- 同一文件在电视、平板、手机横屏和手机竖屏之间的最佳字号不同，仍应保留多预设输出和目标播放器实机检查。

## 29. 只限制字符数仍会读不完，ASR 重叠窗口还会让字幕交错

### 现象与根因

固定的 56 个英文字符、28 个中文字符和 5.5 秒只限制单条上限，没有考虑“这句话实际只显示了多久”。同样 18 个中文字，显示 1.2 秒和 4 秒的阅读压力完全不同。

真实第 4 集旧 checkpoint 还存在更严重的时间轴问题：

- 最终得到 727 个显示事件；
- 按 checkpoint 顺序有 4 次开始时间倒退、11 处相邻重叠；
- 把事件按时间排序后可看到 21 组重叠关系；
- Whisper 滚动窗口把一条完整句和下一条句子识别成重叠区间，旧流程先切分再排序，导致两句话的碎片交错出现。

例如 `I don't even know what disabled sex is.` 与后续 `My husband and I...` 曾在同一时间段交替显示。这类问题不能靠 Qwen 语义去重完全解决，因为错误发生在显示事件的时间排列层。

### 修复

- 在长句切分前先按原识别顺序消解重叠，防止两个来源区间切分后互相穿插。
- 最终排序后再执行一次重叠检查，并为相邻字幕保留约 2 帧间隔。
- 重叠裁剪后不足 0.4 秒的残片直接丢弃，避免屏幕快速闪字。
- 中文按 9 CPS、英文按 20 CPS 计算阅读压力；中文单行目标 16 字、英文单行目标 42 字，最多两行。
- Qwen 的每个目标对象附带按可用显示时间计算的 `ZH_MAX` 和 `SOURCE_MAX`/`EN_MAX`，要求在不丢失原意的前提下压缩过长中文。
- 若下一条字幕前有安全空档，出点最多延长 0.5 秒；不允许与下一条字幕重叠，也不超过配置的最长显示时间。
- 时间报告新增 `overlaps`、`out_of_order`；阅读报告新增最大 CPS、超目标数量和超单行目标数量。

规范依据：

- [Netflix 简体中文规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide)：成人内容 9 CPS、每行 16 个中文字符、最多两行。
- [Netflix 英文规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/217350977-English-USA-Timed-Text-Style-Guide)：成人内容 20 CPS、每行 42 个字符。
- [Netflix 时间规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/360051554394-Timed-Text-Style-Guide-Subtitle-Timing-Guidelines)：入点贴近对白、最低约 20 帧、相邻字幕保留 2 帧间隔，并围绕镜头切换处理出点。
- [Prime Video 字幕规范](https://videocentral.amazon.com/support/delivery-specifications/prime-video-subtitling-guidelines?language=en_US)：通常最多两行、42 字符/行、成人 17 CPS，22 CPS 只作最后手段，并要求结合音频和镜头切换。

### 真实第 4 集离线复算

直接读取现有 source cache/checkpoint 复算，没有抽取音频、没有运行 Whisper、没有重跑 Qwen：

| 指标 | 修复后 |
| --- | ---: |
| 显示事件 | 718 |
| 时间有序 | 是 |
| 重叠 | 0 |
| 小于 0.4 秒的闪烁事件 | 0 |
| 最长显示时间 | 5.42 秒 |
| 中文最大 CPS | 10.67 |
| 中文超过 9 CPS | 7 |
| 英文最大 CPS | 34.31 |
| 英文超过 20 CPS | 103 |

中文仍有 7 条超目标，是因为这些位置前后没有可借用的安全空档；旧 checkpoint 又不会为了提示词升级而自动重写已完成译文。选择“重新校对（保留识别）”后，Qwen 才会按新字符预算重做这些行。英文超目标较多则来自已有/识别源文，当前策略优先保留校正后的源文含义，不会为强行达到 CPS 而确定性删词。

### 尚未自动解决

- 镜头切换点微调需要提取视频场景时间，再在有限窗口内吸附入点/出点；不能跨对白或把字幕延到下一个镜头的关键画面。
- 底部硬字幕/人脸避让和逐镜头 HDR 对比度仍属于后续视觉分析；像素宽度约束已在问题 46 完成。

## 30. 修改提示词或长度规则后，用户只能“继续”或“从头重建”

### 现象与根因

“继续任务”会复用 checkpoint，因此已经完成的旧译文不会应用新的 Qwen 提示词；旧的“从头开始”又会同时删除 `segments.source.json`、embedded/OCR 缓存，导致音频重新抽取并再次运行 Whisper，代价过高。

### 修复

前端运行方式拆成三级：

| 运行方式 | 识别/OCR 缓存 | checkpoint 和 ASS | 用途 |
| --- | --- | --- | --- |
| 继续任务 | 保留 | checkpoint 保留 | 网络中断后续跑 |
| 重新校对（保留识别） | 保留 | 删除并重做 | 应用新提示词、翻译和阅读速度策略 |
| 完全重建 | 删除 | 删除并重做 | 字幕轨、OCR 或 ASR 结果本身错误 |

后端同时保留旧 `restart=true` 请求的兼容行为。清理函数只处理当前输出目录内具有当前片名的流水线文件，不会删除视频旁边的同名 WAV。

## 31. 同项目旧前端仍在运行时，启动器会打开过期页面

### 现象与根因

问题 18 已让启动器通过 `/api/health` 区分字幕项目和其他占用端口的服务，但它只能判断“是不是字幕前端”，不能判断这个进程是否在修改代码之前启动。因此旧实例仍存活时，再运行启动脚本会直接打开旧页面，新增控件看起来像没有实现。

### 修复

- 前端启动时按文件名排序计算全部 `src/*.py` 的组合 SHA-256，并由健康接口返回 `source_sha256`。
- 启动脚本用相同算法计算磁盘上的源码集合，只复用指纹完全相同的进程；网页或 SSH/字幕依赖模块变化都会识别为旧实例。
- 同项目但指纹过期的实例会被跳过，启动器继续寻找空闲端口启动当前代码；不会误杀正在处理任务的旧实例。
- 仍保留 `app=bilingual-subtitle-pipeline` 校验，所以 `8765` 上的其他本地项目不会被当成字幕前端。

## 32. 已有 SSH 私钥，但远程连接仍要求服务器密码

### 现象与根因

当前电脑已经能通过 OpenSSH 密钥登录 `10.12.96.203`，旧前端仍固定显示并提交密码。后端 Paramiko 调用把密码作为位置参数传入，没有解析 `~/.ssh/config`，也没有明确启用密钥文件、SSH agent 或默认密钥；同时使用 `AutoAddPolicy` 自动信任未知主机。

- 远程弹窗新增认证方式层级，默认选择 `SSH 密钥`；密码输入和保存选项只在密码模式出现。
- 默认服务器改为 `10.12.96.203`、用户 `csynth`，仍支持填写别名 `ai-server`。
- 后端解析 OpenSSH 的 `HostName`、`User`、`IdentityFile`、`IdentitiesOnly`、`ServerAliveInterval` 和 `ServerAliveCountMax`。
- 密钥文件留空时优先使用 SSH config；没有配置专用密钥时再使用 SSH agent/默认密钥。
- 显式密钥路径优先于 SSH config，并在连接前检查文件是否存在。
- 加载本机 `known_hosts` 并拒绝未知服务器密钥，不再自动信任中间人可能伪造的新主机。
- 保留旧请求兼容：没有 `auth_method` 但携带密码时继续走密码认证。
- 隧道只有在本地转发端口成功监听后才报告连接成功，状态接口返回实际解析到的主机、用户和认证方式。

## 33. 中英文字幕整体错开时，多句被传递合并成一条

### 现象与根因

旧配对算法把“强时间重叠”建成二分图，再把每个连通分量合并为一对字幕。这个方法可以处理“一条英文对应两条中文”或“两条英文对应一条中文”，但对两条轨道存在稳定偏移的情况不安全。

例如英文每句长 2 秒，中文字幕整体晚 1 秒时，中间英文会同时与前后两条中文达到 50% 重叠。图中的边会沿整段字幕传递，最终把连续多句合并为一个巨大组件。离线复现中，三条英文和三条中文被合成了单个 6 秒事件。

### 修复

- 仍保留一对多和多对一组件合并，兼容两种字幕不同的断句方式。
- 当同一连通分量同时包含多条英文和多条中文时，不再做传递合并。
- 对候选边按重叠比例、重叠时长、中心点距离和起点距离排序，执行一对一匹配；未匹配事件独立保留。
- 新增“整轨晚 1 秒、三句连续字幕”的回归测试，要求输出仍为三对字幕。

这个修复阻止错误扩散，但不会自动校正整条字幕轨相对声音的偏移；真正的音频同步见问题 35。

## 34. 多个网页实例共用固定隧道端口，远程任务可能串到旧实例

### 现象与根因

源码更新后，启动器会保留正在运行的旧前端并启动新端口。旧实现的所有前端都尝试监听本地 `11435`，翻译子进程也固定调用这个端口，因此存在两个问题：

- 新实例可能因端口占用而无法连接远程服务器；
- 更严重的是，新实例即使没有自己的 SSH 连接，也可能把远程模型请求发给旧实例留下的 `11435`，无法证明任务使用的是当前页面显示的服务器。

Windows 上 `SO_REUSEADDR` 还允许多个进程以不符合预期的方式尝试复用同一地址，不适合本地 SSH 转发。

### 修复

- Windows 隧道监听改用独占地址；首选 `11435` 被占用时自动绑定系统分配的空闲端口。
- 前端启动远程任务前必须确认“当前实例”的隧道仍在线，否则直接提示重新连接。
- 当前实例的实际端口通过 `SUBTITLE_REMOTE_OLLAMA_URL` 传给翻译子进程，子进程不再猜测固定端口。
- 远端连接名中的冒号会被规范化，避免破坏 `remote:<连接名>:<模型>` 的路由格式。
- 远端返回的模型名使用 DOM `Option` 节点写入，不再拼接到 `innerHTML`。
- Ollama `keep_alive` 从永久驻留 `-1` 改为默认 `10m`。官方文档说明负数会永久保留模型；现在任务结束后显存会自动释放，也可用 `OLLAMA_KEEP_ALIVE` 覆盖。
- SSH 建连中途失败时显式关闭尚未挂到管理器的 Paramiko 客户端，避免连接资源泄漏。

## 35. 全面审查后仍需继续处理的质量和工程项

> 2026-07-30 状态：本节列出的五组优先事项已按顺序实现，分别记录在问题 36-40；后续镜头切换、整片终审和手机 SRT/真实渲染验证记录在问题 47-54。具体手机播放器兼容性仍需要目标设备验证。

### P1：已有字幕与声音的自动同步

当前流程只在中英文轨之间选择时间锚点，并处理事件内部的长度、重叠和阅读速度；它没有把字幕活动与电影音频进行全局或分段对齐。因此源字幕整体晚 800 毫秒、帧率不同或中途增删片段时，Qwen 校对文本也不能修复时间轴。

推荐分两级实现：

1. 先提供可审计的“检测并预览偏移”，输出全局偏移、置信度和抽样对齐点，不直接覆盖缓存。
2. 置信度足够时允许应用；检测到中途断点或线性漂移时，改用分段对齐并保留映射报告。

可复用的成熟实现：

- [ffsubsync](https://github.com/smacke/ffsubsync) 用 VAD 和 FFT 对齐字幕活动与音频，适合常见全局偏移和帧率差异，但官方说明中段缺失/插入仍是限制。
- [alass](https://github.com/kaegi/alass) 支持常量偏移、帧率差异和广告/导演剪辑造成的分段变化，更适合复杂版本差异。

在真实影片验证前不应默认静默改写时间轴；需要保存原始轨、同步后轨和对齐报告。

### P1：合法重叠字幕仍可能被裁剪

`resolve_timeline_overlaps()` 为避免屏幕闪烁，会裁短或丢弃不足 0.4 秒的前一事件。这个策略适合 Whisper 重叠窗口和 OCR 重复，但对同时说话、画面文字与对白并存的合法字幕可能丢内容。后续应先按来源和文本相似度分类：重复事件可以隐藏，内容不同的重叠事件应合并布局或使用 ASS 层级，而不是统一删除。

### P1：术语一致性只有滑动窗口，没有整片词表

当前 Qwen 会看到最近 `context_lines` 条已批准输出，所以相邻批次的人名通常一致；同一人物隔数百行再次出现时，早期译名已经离开上下文。后续应维护独立的片级术语表，记录源名、批准译名、首次证据和冲突，checkpoint 恢复时同时恢复术语状态。

### P1：checkpoint 没有提示词/策略版本

checkpoint 校验来源、时间、文本和处理模式，但不会因为提示词、模型或阅读规则升级而自动失效。用户必须主动选择“重新校对（保留识别）”。后续应增加处理策略版本与模型标识，并在网页明确显示“可继续”或“需要重新校对”，避免旧译文看起来像新逻辑没有生效。

### P2：字体交付与手机兼容

ASS 使用 `PlayRes` 和相对视频画面的字号，因此播放器缩放视频时会同步缩放字幕；这不是 iOS/Android 的系统动态字体。自定义字体当前只保存 family name，没有打包字体文件。跨设备可靠交付需要提供可选的 MKV 封装步骤，把 TTF/OTF 作为附件写入；MKVToolNix 和 mpv/libass 都支持内嵌字体。仍需在目标手机播放器验证其是否尊重 ASS 样式和附件字体。

### P2：入口、依赖和持续集成

- `audio_to_subtitle.py` 是网页主流程，但 `scripts/run_ready_player_one.ps1` 仍直接执行旧的 `subtitle_pipeline.py` 主入口；旧入口不会经过全部新校对、缓存和时间轴规则，应迁移或明确标记为维护工具。
- 运行依赖分散在两个安装脚本和未锁版本的 `requirements-gpu.txt`，无法稳定复现环境。
- 仓库没有 `pyproject.toml`、锁定文件或 GitHub Actions；当前 89 项测试和 Ruff 只能依赖人工运行。
- `audio_to_subtitle.py`、`subtitle_frontend.py` 和 `subtitle_pipeline.py` 分别超过千行，网页 HTML/CSS/JS 仍内嵌在 Python 中。继续增加功能前应先拆分远程连接、来源分析、任务管理和前端静态资源，减少修改一个页面就触发整个后端指纹变化的范围。

### P2：网页状态持久化

远程配置和表单状态保存在按端口隔离的浏览器 `localStorage`。源码更新后新前端通常使用新端口，因此旧端口保存的配置不会自动出现。SSH 密钥模式只需迁移非敏感配置；密码模式若要跨端口持久化，应使用 Windows 凭据保护或明确的加密存储，不能把明文密码直接写入项目文件。

## 36. 已有字幕相对声音整体延迟、漂移或中途变更

### 现象与根因

中英文轨配对只能解决两条字幕之间的断句和相对时间，不能证明字幕与影片声音一致。内封字幕或网络字幕可能整体提前/延后、由 23.976/25 fps 转换产生线性漂移，或因为广告、片头、导演剪辑不同而在中途改变偏移。LLM 只处理文本，不能根据时间码本身推断声音位置。

### 修复

- 新增 `src/subtitle_sync.py`，固定使用 `ffsubsync==0.5.1`，以所选音频的 WebRTC VAD 为基准，不把视频内另一条字幕误当作参考。
- 启用帧率搜索和 `--split-penalty 20` 的分段偏移，可处理全局延迟、帧率漂移和中途插入/删减。
- 启用两层低质量保护：ffsubsync 会拒绝负相关、超过 45 秒的质量候选或超过 8% 的帧率变化；流程还会拒绝事件数变化、搜索边界截断、乱序、超过 6 次的大幅分段跳变、单条时长变化超过 2 秒、非正时长和后端异常。
- timing SRT 为每个事件写入稳定标记，ffsubsync 即使重排输出块也会按原事件 ID 映射，不把输出顺序误当作输入顺序。
- 分段候选未通过流程质量门时再运行一次无分段的安全全局对齐。全局结果合格则报告 `aligned_global_fallback` 并使用它；仍不合格就保持原时间。
- 前端“已有字幕”层级新增 `自动校正 / 仅检测并生成报告 / 关闭`。自动模式只在后端报告成功时应用；检测模式永远保持原时间。
- 输出 `<片名>.subtitle-sync.report.json`，记录后端、模式、事件数、全局偏移、帧率比例、中位起点变化、P95/最大绝对变化和是否实际应用。
- 被修改事件保留 `pre_sync_start/pre_sync_end`，source cache 记录同步后的确定性输入。同步模式进入来源请求指纹，更换模式后不会误用旧缓存。
- 只有 sidecar/embedded 来源运行同步；Whisper ASR 已经直接由当前音频生成时间锚，不重复抽音频、识别或占用本地 GPU。

同步仍不能替代镜头切换吸附。镜头时间吸附已在问题 51 独立实现；两者都不分析字幕是否挡住画面内容。

## 37. 合法同时对白被统一重叠清理删除

### 现象与根因

旧的 `resolve_timeline_overlaps()` 把所有重叠都视为滚动识别碎片。前一事件被裁后不足 0.4 秒就直接删除，因此两人同时说话、对白与屏幕文字并存时会丢掉真实内容。

### 修复

- sidecar、embedded 及中英合并事件增加 `preserve_distinct_overlap` 来源标记，ASR 事件不带该标记。
- 重叠处理同时比较规范化后的实际显示内容。两个已有字幕事件内容不同且都允许重叠时保留原始起止时间，由 ASS `Collisions: Normal` 负责堆叠布局。
- 相同内容、LLM 标记隐藏的重复项、Whisper/OCR 滚动碎片仍走原有去重、裁剪和 0.4 秒闪烁保护。
- 时间报告把重叠拆成 `intentional_overlaps` 和 `unexpected_overlaps`，合法重叠不再伪装成时间轴错误。
- 回归测试覆盖“短碎片仍删除”和“两个不同的来源字幕同时存在且均不丢失”。

## 38. 人名远距离漂移及旧 checkpoint 静默冒充新策略

### 现象与根因

滑动上下文只能约束附近批次。同一人物隔数百行再次出现时，早期译名已经离开上下文；切换 `qwen3:14b`/`qwen3:30b` 或升级提示词后，旧 checkpoint 又可能直接续跑，使新规则看起来没有生效。

### 修复

- Qwen 每个目标对象新增 `terminology` 字段，只返回本句出现的人名和复现术语。
- 程序采用“首次批准映射优先”的片级字典；后续批次无论 `context_lines` 是否为 0，都会收到完整的 `APPROVED MOVIE-WIDE TERMINOLOGY`。
- 每批输出还会做确定性一致性检查。源文出现已批准人名/术语但中文没有对应译名，或模型提出冲突映射时，会进入单句重试；重试后仍冲突则中断该批并保留最后一个有效 checkpoint。
- 片级状态随每个 checkpoint 批次写入段落元数据，并独立输出 `<片名>.terminology.json`；断点恢复时从已验证的 checkpoint 重建，不读取来源不匹配的陈旧词表。
- 每个 checkpoint 段落记录 `llm_model`、`processing_policy_version` 和 `terminology_policy_version`。
- checkpoint 校验新增模型与策略版本。任一不匹配就从现有 source cache 重新校对，不重新抽音频或运行 OCR/Whisper。
- 前端分析结果显示不兼容状态，并把默认运行方式从“继续任务”切到“重新校对（保留识别）”。

## 39. 手机换设备后自定义字体丢失

### 现象与根因

ASS 的 `PlayRes` 能让字号随视频画面缩放，但 `.ass` 只有 family name，没有字体数据。目标手机没有该字体时，播放器只能回退，中文覆盖、字重和实际宽度都可能变化。

### 修复

- “字幕外观”新增 TTF/OTF/TTC 文件选择，只有展开外观设置时显示。
- 新增 `src/font_delivery.py`，使用 `fonttools` 读取字体内部首选 family name；选择文件后以内部名称生成 ASS，避免把文件名误当字体族。
- 字体复制到输出目录 `fonts/`，原始字体文件不修改。
- 使用现有 ffmpeg 生成 `<片名>.bilingual.mks`，其中包含双语 ASS 轨和字体 attachment；这是小型外置 Matroska 字幕包，不复制整部影片。
- 输出 `<片名>.bilingual.font-delivery.json` 记录 ASS、字体、family name 和 MKS 路径。
- 已用 Windows Arial 字体做真实封装验证，生成的 MKS 包含约 1 MB 字体附件。

`adaptive/mobile/compact` 仍按视频画面自适应，不等同于 iOS/Android 系统动态字号。手机播放器必须支持 ASS/libass 和 Matroska 字体附件；不支持的播放器仍可能覆盖样式，需要在目标设备实测。

## 40. 双入口、漂移依赖、无 CI 以及新端口丢设置

### 现象与根因

示例脚本仍调用旧 `subtitle_pipeline.py` 的独立翻译流程；安装脚本使用未固定版本的散落依赖；仓库没有自动测试。前端表单和远程服务器配置只存在当前端口的 `localStorage`，更新源码换端口后看起来像所有设置丢失；保存密码还会留下浏览器明文。

### 修复

- `src/audio_to_subtitle.py` 成为唯一正式处理入口。`scripts/run_ready_player_one.ps1` 已切换；直接运行旧入口时只保留 `--list-streams` 工具能力，其余兼容参数转发到正式入口。
- 新增 `requirements.txt`、`requirements-ci.txt`、`requirements-dev.txt` 和 `pyproject.toml`；直接依赖固定精确版本。GPU/OCR 依赖通过 `requirements-gpu.txt` 叠加，CUDA 13 Paddle wheel 仍由专用脚本安装。

- 新增 `.github/workflows/ci.yml`，在 Windows/Python 3.13 执行 Ruff、`compileall` 和完整 `unittest`。
- 同步、字体、策略和前端设置分别拆到独立模块，减少继续扩大两个主文件的范围。
- 新增 `%LOCALAPPDATA%\BilingualSubtitlePipeline\frontend-settings.json` 服务端设置。页面保留当前端口 `localStorage` 作为快速缓存，同时异步同步到服务端；新端口先加载服务端状态再叠加本端口状态。
- 旧浏览器中存在明文密码时会迁移到服务端保护存储，并立刻从 `localStorage` 删除密码字段。
- 密码只在密码认证且明确勾选时保存，使用当前 Windows 用户的 DPAPI 加密；JSON 文件只含 Base64 密文。SSH 密钥内容始终不进入浏览器或配置文件。
- 前端只允许绑定 `localhost`、`127.0.0.1` 或 `::1`，每个请求还校验 loopback Host，降低 DNS 重绑定读取本地配置的风险。
- 有请求体的接口只接受 `application/json` 对象并限制为 1 MiB；设置只接受受限数量的标量字段，避免跨站表单和异常大载荷滥用本地接口。

## 41. Windows 短路径中的 `~` 被误当作 SSH home 展开

### 现象与根因

GitHub Windows Runner 的临时目录可能使用 `RUNNER~1` 这类 8.3 短路径。Paramiko 在展开 OpenSSH `IdentityFile` 时会把绝对路径中间的 `~` 也替换成用户 home，形成类似 `C:\Users\RUNNERC:\Users\runneradmin1\...` 的无效路径。该问题同样可能影响真实配置中包含短路径的密钥。

### 修复

- SSH config 的主机、用户、端口等继续使用 Paramiko 完整 lookup 结果。
- 对不含 OpenSSH `%` token 的绝对 `IdentityFile`，从匹配后的未展开配置保留原路径；`~/.ssh/...` 和带 `%` token 的相对模板仍使用 Paramiko 展开结果。
- 回归测试固定使用包含 `runner~1` 的绝对密钥路径，确保本地与 GitHub Windows Runner 行为一致。

## 42. 选择了远程同步音轨，但已有字幕模式没有提交；中英轨还会先合并再同步

### 现象与根因

前端只在“音频识别”来源下提交 `audio_stream`。已有 sidecar/embedded 字幕即使选择了某条音轨，后端仍收到空值，只能自动选轨。更严重的是，旧流程先按原时间合并中英文轨，再把合并后的事件统一交给 ffsubsync。两条字幕轨各自存在不同偏移时，合并过程已经可能错配，后续统一移动无法恢复正确关系。

### 修复

- “已有字幕 + 同步不是关闭”时按层级显示“用于字幕同步的音轨”，关闭同步后自动隐藏。
- `payload()` 在已有字幕同步、音频识别和尚未完成自动分析三种需要音轨的状态下提交选择；不相关来源仍提交空值。
- sidecar 和 embedded 加载器改为保留独立的中文、英文事件列表；原有返回合并列表的函数保留为兼容包装。
- 两条轨分别对齐同一视频和同一 `audio_stream`，通过后才调用中英配对。
- 自动模式采用原子策略：两条轨都通过质量门才使用同步结果；一条失败时两条都回退。中文字幕单轨则只要求该轨通过。
- 报告增加 `scope=per_track`、中英文事件数、逐轨报告和 `reverted_all_tracks`。
- `SYNC_POLICY_VERSION` 升至 6，`SOURCE_CACHE_VERSION` 升至 4；旧的“先合并后同步”缓存不会继续复用。
- 同步策略升级不会牵连 Whisper：旧策略指纹的 `timing_origin=audio_asr` source cache 仍可复用，并在本次输出后升级指纹；只有已有字幕时间源会因同步策略变化重新提取字幕轨和对齐，不会重新 OCR/ASR。

## 43. 双语每种语言实际只有一行，却按两行额度生成超长字幕

### 现象与根因

双语 ASS 的布局固定为第一行中文、第二行源文，但提示词预算把 `16 × 2` 中文字符和 `42 × 2` 英文字符都当作单种语言可用空间；最终断句又使用最多 28 个中文字和 56 个英文字符。结果是单条字幕字符数看似没有超过“总预算”，实际播放时每种语言各自的一行已经过长。

### 修复

- 双语中文硬上限改为每条 16 字，英文硬上限改为每条 42 字；`--max-chars` 只能进一步收紧英文上限，不能放宽专业布局上限。
- 时长预算的长事件上限同步改为 `ZH_MAX=16`、`SOURCE_MAX=42`，不再给每种语言重复分配两行。
- 中英文独立计算所需分段数，再使用同一个分段数保持双语时间对应。
- 均分算法加入标点权重：优先在中英文句号、问号、感叹号、逗号、分号和冒号后切分；英文避免把冠词、介词、助动词留在行尾。
- 前端旧的 56/82 字符设置自动迁移到 42，输入控件不再允许设置大于 42。
- 回归测试验证长双语事件的每个中文片段不超过 16 字、英文不超过 42 字，重组后文本不丢失，并验证中英文标点边界。

## 44. `qwen3:30b` 在 OpenAI 兼容接口中持续思考，结构化正文为空

### 现象与根因

远程 Ollama `0.30.11` 的 `/v1/chat/completions` 实测没有按兼容请求中的 `think=false` 关闭 `qwen3:30b` 思考。最小请求的 512 个输出 token 全部进入 `message.reasoning`，`message.content` 为空并以 `finish_reason=length` 结束。这样即使客户端传入 JSON Schema，也拿不到可解析的字幕对象。

### 修复

- 模型调用改用 Ollama 原生 `/api/chat`；本地和 SSH 隧道远端使用同一接口。
- `think=false`、`format=<JSON Schema>`、`keep_alive` 和全部采样参数由原生字段提交，不再依赖 OpenAI 兼容映射。
- 新增 `src/llm_policy.py`，固定三类角色：

| 角色 | temperature | top_p | top_k | seed | num_ctx | num_predict |
|---|---:|---:|---:|---:|---:|---:|
| 元数据 | 0.0 | 0.8 | 20 | 41 | 8192 | 512 |
| 翻译 | 0.15 | 0.8 | 20 | 42 | 32768 | 4096 |
| 双语校对 | 0.1 | 0.8 | 20 | 43 | 65536 | 4096 |

- 翻译 Schema 强制 `index/corrected_text/chinese_translation/display/terminology`；校对 Schema 强制 `index/corrected_english/corrected_chinese/display/terminology`，并限制数组条数和索引范围。
- 程序在 Schema 之后再次校验对象数、索引完整性、字段类型、布尔显示标记、术语数组和语言有效性。
- checkpoint 记录 `llm_role` 及完整 `llm_generation_profile`；`PROCESSING_POLICY_VERSION` 升至 4，旧模型输出会从 source cache 重新校对而不会重新 OCR/ASR。
- 删除不再需要的 `openai` 直接依赖。

远程 `qwen3:30b` 原生接口实测在约 2 秒内返回并通过完整 Schema：

```json
[{
  "index": 0,
  "corrected_text": "The storm is getting worse.",
  "chinese_translation": "风暴正在加剧。",
  "display": false,
  "terminology": []
}]
```

该最小请求没有提供真实批次中的上下文和“正常对白应显示”规则，所以 `display=false` 只用于验证字段约束，不作为翻译质量样本。

## 45. Qwen 可能把正常且唯一的字幕误标为隐藏

### 现象与根因

模型输出契约允许用 `display=false` 合并 ASR/OCR 重复循环，但旧流程直接信任该布尔值。即使 JSON Schema、语言字段和索引都完全合法，模型仍可能把一条没有重复的正常对白标为隐藏。隐藏项又跳过语言有效性检查，因此一旦后处理恢复显示，还可能没有完整中文。

### 修复

- 每个模型隐藏请求增加确定性覆盖检查，不再把模型判断直接当作删除命令。
- 只接受三类可证明的情况：与较早相邻可见项完全重复、源文已被较早完整句包含、或高相似度近重复；时间距离默认不超过 4 秒。
- 不允许隐藏较早事件而只保留更晚事件，避免字幕在对白开始后才出现。
- 无法证明覆盖的唯一源文强制恢复为可见，并记录 `model_display_requested=false`、`display_guard=forced_visible` 和原因。
- 如果被恢复的字幕缺少有效中文，单句重试会明确要求 `display=true` 和完整译文；仍请求隐藏或语言无效时继续重试，最终失败则保留最近 checkpoint。
- 已确认覆盖的隐藏项记录 `display_guard=accepted_hidden`；最终质量报告分别统计接受隐藏和强制恢复数量。
- 旧 checkpoint 恢复时也执行同一保护，不需要重新抽取音频、OCR 或 Whisper。

## 46. 字符数合格但自定义字体或窄画幅仍可能溢出，且没有成片级报告

### 现象与根因

16 个中文字和 42 个英文字符只是通用上限。同样的字符数在宽字体、160% 字号、竖屏/窄画幅或手机大字方案中可能超过 ASS 左右安全边距。旧流程只在控制台打印 CPS 和字符数，没有持久化像素宽度、模型误隐藏、缺译、结构性时间错误等结果；前端也只能显示“完成”，无法区分可以交付和需要复核。

### 修复

- `src/ass_styles.py` 新增统一的已解析样式指标，ASS 头和质检共用实际字号、左右边距、描边、阴影及安全行宽，避免两套公式漂移。
- 新增 `src/subtitle_quality.py`。选择 TTF/OTF/TTC 时通过 `fonttools` 读取 cmap、`hmtx` 和 `unitsPerEm` 计算 glyph advance；未选择字体文件时使用按 East Asian Width、空格、窄字符和宽字符分类的保守 Unicode 估计。
- 在最终双语拆句前先读取视频 `PlayRes`、显示方案、字体和字号。像素宽度需要更多分段时，与 16/42 字符、12 词和 5.5 秒限制共同决定分段数。
- 中文和源文仍使用相同事件数和时间片，避免一条轨单方面增加事件导致双语时间错位；日语、韩语等无空格东亚源文按字符拆分，不会因兼容字段名 `en` 被丢弃；无法安全拆开的超长拉丁单词不会被静默截断，而会留在报告中复核。
- 每次成片原子输出 `<片名>.quality-report.json`，状态为 `pass`、`review` 或 `fail`。
- 报告覆盖像素溢出、中文/英文/东亚源文 CPS、最长时长、非正时长、意外重叠、空事件、缺少中文、中文轨仍是外文、英文来源轨意外混入东亚文字、术语冲突、模型隐藏恢复及交付文件路径；合法日语/韩语源轨按来源语言豁免，样本列表有上限，避免整片报告无限膨胀。
- 合法同时对白按 `intentional_overlap_count` 单列，不计入失败。
- 结构性错误标记 `fail` 并让任务失败；可读性、缺译或隐藏保护等需要人工判断的项目标记 `review`，保留已生成字幕。
- 前端“状态”增加“成片质检”，显示“通过 / 建议复核 / 未通过”、报告路径和关键数量；重新校对或完全重建时清理旧报告，运行中显示“待更新”。

像素宽度解决的是字幕文本在 ASS 安全区域内的排版，不等于真实画面内容分析。镜头切换吸附已在问题 51 完成；人脸/烧录字幕避让和 HDR 场景对比度仍需要独立的视频视觉分析与目标播放器实测。

## 47. 最终质检没有覆盖同步失败、极短字幕和错误字幕轨

### 现象与根因

旧质量报告只检查最终文本、CPS、像素宽度和基本时间结构。`ffsubsync` 被拒绝、已有字幕关闭同步、电影误选 forced/signs 稀疏轨，以及最终事件短于约 20 帧时，报告仍可能显示通过。恢复 source cache 时还没有重新载入已有同步报告，导致同步证据丢失。

### 修复

- 质量报告版本升至 2，新增 `subtitle_sync`、`source_completeness` 和最终最短时长检查。
- 已有字幕源缺少同步报告、同步关闭、仅检测未应用、低质量拒绝或逐轨部分失败时标记 `review`，保留具体原因。
- 用 ffprobe 读取电影片长，计算来源字幕的事件数/分钟和时间覆盖率；长片中事件极少且覆盖率很低时提示可能选中了 forced/signs 轨，不自动删除或换轨。
- 最终事件短于 `20/24` 秒进入复核，非正时长和意外重叠仍属于结构性失败。
- source cache 恢复时同步读取 `<片名>.subtitle-sync.report.json`，并把同步报告加入交付文件清单。

## 48. Whisper 和 PGS OCR 的置信度被丢弃

### 现象与根因

faster-whisper 已提供词概率、平均 log probability、压缩率和无语音概率；PaddleOCR 也返回每行识别分数。旧代码只缓存文字与时间，后续 Qwen 和人工复核无法区分可靠对白与高风险识别结果。

### 修复

- ASR source cache 持久化 `asr_avg_logprob`、`asr_compression_ratio`、`asr_no_speech_prob`、语言概率、平均词置信度和每词 `probability`。
- 自动语言识别显式使用 multilingual 模式，并启用 faster-whisper 的 hallucination silence threshold。
- PGS OCR 新增结构化 `OcrObservation`，保存平均置信度和逐行置信度；OCR cache 升至版本 3，同时兼容并可续跑版本 2。
- PaddleOCR 新格式中的 `rec_scores` 可能是 NumPy 数组，读取时不再做会触发“truth value is ambiguous”的布尔转换。
- OCR 置信度随内封字幕加载、一对多/多对一合并和 source cache 继续传递。
- 最终报告新增 `recognition_confidence`。OCR `<0.75`、ASR 平均 log probability `<-1.0`、压缩率 `>2.4`、无语音概率 `>0.6` 或低置信词比例过高时只标记对应事件复核。

这些阈值用于筛选人工复核，不是把模型分数当成绝对正确率，也不会自动删除字幕。

## 49. 网页只能显示“建议复核”，不能定位或修正具体字幕

### 现象与根因

质量报告已经包含样本，但前端只显示总状态和报告路径。用户必须手工打开 JSON，再寻找 checkpoint 中对应事件；修正后也没有明确的重新生成流程。

### 修复

- 前端把所有 `review/fail` 检查展平为“成片复核”表格，可按时间轴、识别置信度、同步、术语、整片风格、独立终审和渲染等问题类型筛选。
- 有事件 ID 的样本自动关联 checkpoint 中的完整英文、中文和时间；全局问题保留报告原因。
- “复核”入口可修改开始/结束时间、英文、中文和显示状态。保存采用原子文件替换，保留其他元数据，并记录 `manual_reviewed_at`。
- 第一次人工修改会同时保存 `manual_source_start`、`manual_source_end` 和 `manual_source_text`。断点恢复用这些来源锚点验证 source cache，而不是把人工调整后的显示时间误判为来源变化；独立终检也不会覆盖已人工确认的行。
- 最终输出拆分保留 `checkpoint_segment_id`，质量报告即使引用重编号后的显示事件，也能回到正确的 checkpoint 行，不会把问题展示到相邻字幕。
- 独立终审拒绝项和 ASS 渲染失败样本也会进入同一定位链路，不再只显示无法操作的全局错误。
- 用事件 ID 和旧开始时间做乐观并发校验；任务运行中拒绝修改，避免前端与处理子进程同时写 checkpoint。
- 保存后质量报告标记 `manual_review_pending`，明确要求运行“继续任务”重新生成 ASS/SRT 和质检报告，不伪装成成片已经同步更新。

## 50. 长双语字幕被等分时间，后半句在对白说完后才出现

### 现象与根因

翻译后的双语文本需要再次按 16/42 字符拆分。旧 `split_bilingual_segment()` 无论是否有词级时间戳，都把原事件时长平均分配给各片段。对白中存在停顿时，均分点与真实发音完全无关；已有字幕没有词锚点时，程序还会凭空制造后续入点。

### 修复

- 双语拆分优先按源文片段权重把 faster-whisper 词时间戳分组，每个显示事件使用该组第一个词的入点和最后一个词的出点。
- 词级元数据随拆分片段保存，后续镜头吸附不能截断最后一个词。
- 已明确标记 `timing_origin`、但没有词级锚点的来源事件不再做顺序等分；保留原 cue 时间和文本，并记录 `unanchored_split_avoided`。过长文本由质量报告提示复核，而不是以错误时间换取表面长度合格。
- `SOURCE_CACHE_VERSION` 升至 5；旧的已有字幕等分缓存会重建，纯 ASR cache 仍可复用。

## 51. 字幕时间没有利用镜头切换，容易短暂跨镜

### 现象与根因

音频同步解决字幕与语音的整体偏移，词时间戳解决句内发音锚点，但两者都不知道画面何时切镜。字幕入点晚于切镜约 100 毫秒或出点在切镜后残留很短时间时，视觉上仍不专业。

### 修复

- 新增 `src/scene_timing.py`，用 ffmpeg 将画面降至 320 像素宽、每秒抽样 6 帧并以 scene score `0.35` 检测切点。
- 结果写入 `<片名>.scene-cuts.json`，缓存绑定视频绝对路径、大小、修改时间和检测参数；恢复任务不重复分析整片。
- 字幕边缘只在 0.25 秒窗口内吸附：入点只向前贴近刚发生的切镜，不把字幕延后；出点可向附近切镜伸缩。
- 调整仍受最短时长、最长时长、相邻 2 帧间隔和词级首末锚点约束；无法安全吸附时保持原时间。

场景检测是低成本时间提示，不识别人脸、烧录字幕、UI 或 HDR 局部对比度。底部画面避让仍需要独立视觉分析和目标播放器验证。

## 52. 第一批翻译前没有整片风格，人名只能边做边定

### 现象与根因

片级术语表能够锁定“首次批准”的译名，但第一批仍在没有全片信息的情况下决定名字、称谓、语气和 SDH 风格。如果角色在后半段才暴露身份，早期偶然选择会传播到整片；同一个模型完成批次后也没有独立终审。

### 修复

- 对不少于 12 个事件的任务，先从全片均匀抽样最多 180 条、约 24,000 字符，调用所选 Qwen 模型生成 `<片名>.style-guide.json`。
- 风格指南固定口语/正式语域、人名策略、称谓、SDH 补译和中文标点；有充分证据的名字和复现术语在第一批翻译前写入批准词表。
- 风格缓存绑定完整来源字幕指纹、模型和策略版本，切换字幕或模型后不会沿用旧指南。
- 首轮完成后运行独立 `proofread` 角色终审，按批检查残留 ASR/OCR 错误、错译、人名、称谓、术语、SDH 和中文完整性。
- 终审保持时间和显示决定不变，逐批原子写入 `<片名>.final-qa.json` 并可从已完成批次恢复；无效语言或术语结果不覆盖首轮字幕，而是进入最终复核。
- `corrected_english` 仅是兼容旧 Schema 的字段名，实际代表“源语言轨”。首次校对和终审都会携带 `SOURCE_LANGUAGE`，并验证英语、日语、韩语等原语言与文字系统；把日语/韩语源文翻成英文的结果会被拒绝或单句重试。
- 带 `manual_reviewed_at` 的人工确认行在独立终审中只记录为已检查，不允许 Qwen 再次改写。`FINAL_QA_POLICY_VERSION` 升至 2，使旧终审缓存不会绕过新保护。
- checkpoint 写入终审结果；输入/输出指纹避免恢复任务重复终审已经一致的文件。
- `PROCESSING_POLICY_VERSION` 升至 5，`TERMINOLOGY_POLICY_VERSION` 升至 2。旧 checkpoint 从 source cache 重新校对，不重新 Whisper/OCR。

## 53. 只有 ASS，手机系统字号和真实渲染兼容性不可验证

### 现象与根因

ASS 能保留专业排版和字体附件，但手机播放器可能覆盖 ASS 样式，且 ASS 无法跟随 iOS/Android 系统字幕字号。旧流程也只验证文本文件写出成功，没有证明 ffmpeg/libass 能真正渲染所选样式。

### 修复

- 新增 `src/subtitle_delivery.py`，同时输出英文、简体中文和双语 `.srt`；双语 SRT 为“中文在上、源文在下”。
- SRT 不携带固定字体，适合需要播放器系统字体、无障碍字号或手机屏幕动态设置的场景；ASS 继续用于需要固定字号、描边、位置和自定义字体的播放器。
- 每次生成双语 ASS 后，ffmpeg/libass 会在第一条可见字幕的实际时间戳渲染一帧 `<片名>.render-preview.png`。
- 程序读取 PNG 并检查非背景像素，结果写入 `<片名>.render-validation.json`；无字幕像素、滤镜失败或字体/ASS 解析异常进入 `delivery_render` 复核。
- 交付模块独立打包，项目版本升至 `0.4.0`。

手机端建议：优先试双语 SRT 并由播放器控制字号；需要固定设计时使用 `mobile` ASS 方案和字体 MKS 包。任何单一文件都不能保证所有手机播放器同时尊重 ASS 样式、系统无障碍字号和内嵌字体。

## 55. 内封文本、图像字幕、外置字幕和 ASR 被同一种策略处理

### 现象与根因

旧流程只有 `sidecar / embedded / audio` 三个入口，没有持久化“这段文字是人工字幕、OCR 还是 ASR”“它是完整对白、SDH、forced 还是评论轨”“时间轴是否来自片源本身”等证据。因此会出现几类相互冲突的问题：

- 人工英文字幕可能被 Qwen 当作识别结果改写或隐藏。
- OCR/ASR 的明显错误又可能因为“保留原文”而没有被修复。
- 有中文时仍可能走音频识别，远程 Qwen 翻译期间本地 GPU 看起来仍在执行。
- 普通英文轨没有音乐或环境提示，而英文 SDH 独有内容没有进入中文轨。
- 网页推荐的来源和后端 `auto` 实际选择不同；内封中文与外置英文也不能组合。
- source cache、翻译 checkpoint 和最终终审没有共同绑定来源处理方案。

### 修复

- 新增 `src/subtitle_sources.py`，为每条候选来源建立稳定的 `SubtitleAsset`：
  - `origin`：`embedded / sidecar / audio`
  - `representation`：`authored_text / bitmap_ocr / speech_asr`
  - `language / script / role / codec`
  - `text_authority / timing_authority`
  - 文件路径或容器 stream index、disposition、匹配分数和可用性
- 优先使用 ffprobe JSON 读取 `default / forced / hearing_impaired` 等 disposition；ffprobe 不可用时继续兼容原 ffmpeg 文本解析。
- codec 采用完整 token 分类，避免把 `dvb_teletext` 因包含 `text` 误判为可提取文本。当前只有 PGS 进入图像 OCR；DVD/DVB/XSub/Teletext 等未实现格式在计划中警告，网页选项禁用，不会运行错误的 OCR 路径。
- 自动选择改为确定性处理计划：
  - 人工文本优先于图像 OCR，图像 OCR 优先于音频 ASR。
  - 同等条件下内封人工轨获得质量加权；同片名外置轨仍保留匹配加权。
  - 中文轨优先普通完整对白和简体，繁体先确定性转简体再保守校对。
  - 源语言轨优先英文 SDH，使普通轨没有的音乐、说话者和环境提示进入“中文为空才补译”的流程。
  - forced 轨不能冒充完整对白，只从与主源语言匹配的候选中选择质量最高的一条作为补充；评论轨不参与自动选择。
- 后端 `auto` 使用与网页相同的来源评分，不再固定先尝试外置字幕。支持内封中文与外置英文、外置中文与内封英文的跨来源组合。
- 多来源合并会按时间和标准化文本去重；不同的 forced/SDH 提示保留为独立事件。补充来源只绑定它实际贡献的事件，不再把补充轨错误写进每条主对白的来源记录。英文音效提示会先按音效类别和强时间重叠查找已有中文提示，匹配成功就组成同一事件；只有中文确实为空时才交给 Qwen 补译。
- 处理计划新增 `audio_reference`。自动选择的同步/识别音轨进入处理计划指纹；音轨变化后不会误用旧 source cache。只有 commentary/无障碍解说音轨时：
  - 已有字幕保留原时间，`subtitle-sync.report.json` 标记 `skipped_unsafe_audio_selection`。
  - 需要 Whisper 时直接停止并要求明确选轨，避免把评论内容识别成电影对白。
- 人工源文增加硬保护：
  - 模型即使返回不同 `corrected_english`，程序也恢复人工原文。
  - 模型不能隐藏人工来源事件。
  - OCR 和 ASR 仍可依据置信度、上下文和重复证据修复。
- prompt 为每个事件携带 `SOURCE_AUTHORITY`、`CHINESE_AUTHORITY` 和 `RECOGNITION_RISK`。OCR `<0.75`、ASR 低 log probability、高压缩率、高无语音概率或低词置信度会进入优先复核。
- 每次任务输出：
  - `<片名>.source-manifest.json`
  - `<片名>.processing-plan.json`
- 处理计划记录中文轨、源语言轨、补充轨、字幕时间基准、同步音轨、操作步骤和计算位置。运行期另记 `execution.source_cache_reused`：
  - 首次 PGS/OCR 或 ASR 才列入本次本地 GPU。
  - 从 source cache 继续时，本次 `execution.local_gpu=[]`，不会把“来源重建所需 GPU”误报为“本次正在执行”。
- source cache 继续独立于翻译 checkpoint：
  - `SOURCE_CACHE_VERSION` 升至 6，只让旧的已有字幕时间策略重建；纯音频 ASR 旧缓存仍可兼容。
  - `PROCESSING_POLICY_VERSION` 升至 6、`FINAL_QA_POLICY_VERSION` 升至 3。
  - 翻译 checkpoint 校验 `processing_plan_fingerprint`；最终终审指纹同时包含来源权威和处理计划。
- 网页增加“推荐处理方案”，明确显示具体中文轨、源语言轨、补充轨、字幕时间基准、同步音轨、处理步骤和本地/远程计算位置。只有实际选择图像字幕时才显示 OCR 语言；混合来源保持 `auto`，不伪装成单一 sidecar 或 embedded 模式。
- “分析视频”严格按当前 `auto / sidecar / embedded / audio` 模式、具体字幕文件/stream、同步音轨和同步开关生成方案，不再用全局自动结果覆盖显式选择。改动任一来源条件后立即隐藏旧方案，重新分析前不会继续展示过期结论。
- 字幕文件、字幕 stream 和音频 stream 选择只属于当前分析的视频，不再写入全局表单设置；切换路径时立即清空，避免另一部电影恰好使用相同 stream index 时被误判为用户明确选轨。评论/解说音轨在网页选项中单独标记并禁用；命令行显式指定仍保留为诊断边界。
- 与视频无文件名匹配关系的同目录字幕仍显示供手动选择，但不会进入自动处理计划。

## 57. 夜间任务只有一轮终审，仍需要人工逐条打开复核

### 现象与根因

原流程会执行片级风格分析、术语审查和一次独立终审，但成片质量报告中的复核项仍只提供人工入口。长片在夜间运行时，一轮模型审查可能遗漏上下文串行、识别残错、译名漂移或不自然的中文；如果远程模型在终审末段失败，也没有独立的夜间审计状态说明已经完成到哪一轮。

### 修复

- 网页“高级设置”新增一个层级化开关：`夜间无人值守复核（2 轮）`。默认关闭，避免普通任务无意增加两倍终审成本；启用后沿用当前选择的本地或远程模型，推荐使用远程 `qwen3.5:122b`。
- 第一轮使用 `semantic_integrity` 角色，检查 ASR/OCR 残错、缺失或虚构信息、数字、人名、称谓、说话人标签，以及中文缺少的英文 SDH/音乐/音效提示。
- 第二轮使用 `professional_readability` 角色，检查专业中文字幕表达、全片人名与语域一致性、明确的标点歧义和难以阅读的措辞。两轮都要求“只有存在可证明缺陷才修改”，禁止为了风格偏好反复改写或删减事实。
- 命令行可用 `--autonomous-review-rounds 0..3`；第三轮 `adversarial_residual` 用于额外检查相邻时间段串词、重复识别循环、语言/文字系统变化和双轨信息缺失。网页保持单一开关，不把轮数和角色继续暴露成一组平铺选项。
- 每轮继续使用既有的来源权威、术语表、语言/文字系统、上下文借用、中文内容保留、时间轴不变和结构化 JSON 校验。模型不能改时间，不能改人工字幕源文，也不能覆盖带 `manual_reviewed_at` 的人工确认行。
- 汇总审计写入 `<片名>.autonomous-review.json`，每轮批次断点分别写入 `<片名>.autonomous-review.round-N.json`。断电、网络中断或前端重启后会从该轮最近完整批次继续，不会重新抽取音频、OCR 或运行 Whisper。
- 每轮完成后原子保存汇总；全部完成后才把最终已验证文本写回 `segments.checkpoint.json`。checkpoint 已经等于自治复核输出时，再次“继续任务”直接复用结果，不重复调用大模型。
- 某一轮失败时保留上一轮完整有效文本并继续生成 ASS/SRT、渲染预览和质量报告；自治审计状态记为 `failed`，成片质检显示需要复核，不会把降级结果伪装成通过。修复远程服务后再次运行会继续失败的那一轮。
- 大模型复核完成后仍依次执行现有的确定性排版、镜头切点、阅读速度、时间结构、来源完整性、真实 libass 渲染和质量报告工具。LLM 不能自行批准同步失败、像素溢出或渲染错误。

### 使用边界

夜间自治复核提高的是文本审查覆盖率，不等于专业人员逐镜听校。音画同步、烧录字幕遮挡、人脸/UI 避让、特殊口音和复杂角色关系仍可能进入“建议复核”；这些问题会保留证据和具体事件，不会被自动隐藏。

## 58. 页面重开后远程模型、运行状态和字幕轨看起来仍然有效

### 现象与根因

- 上一次选择远程模型后，如果新网页实例没有恢复 SSH 隧道，浏览器给只有本地模型的下拉框赋远程值会得到空值。提交时后端把空模型解释成默认 `qwen3:14b`，用户以为仍在远程翻译，本机 Ollama 实际开始占用 GPU。
- 页面只要恢复了系列名和片名就查询状态；旧日志名只由这两个名称组成。另一个输出根目录中同名任务的成功日志也可能让当前页面显示“已完成”，即使当前输出目录并不存在。
- 页面恢复输入后允许立即运行，但内封字幕轨、同步音轨和处理计划还没有重新分析；来源下拉框只有“自动选择”占位符，无法证明即将使用哪一轨。
- 启动脚本只检查 `8765..8775`。历史前端占满该范围、最新版运行在更高端口时，脚本既不能复用最新版，也会继续制造端口和页面混乱。
- 多语言发布名中的连续轨道标签（例如 `Eng.Fre.Ger.Ita...`）不属于常规分辨率/编码标签，启发式片名会把它们保留下来，生成极长且错误的输出目录。

### 修复

- 恢复一个当前不可用的远程模型时，模型下拉框明确显示“需重新连接”，运行按钮保持锁定；只有用户重新连接远程服务器，或明确改选本地模型后才能运行。远程断开不再静默回退本地 GPU。
- 模型字段下方持续显示计算位置；运行前确认区汇总字幕来源、模型位置、标准/夜间复核策略和输出目录，并给出唯一的阻断原因。
- 没有与当前路径匹配的分析结果，或来源/字幕轨/同步设置已使处理方案失效时，必须重新“分析视频”。分析结果携带当前来源配置指纹，跨端口恢复的旧处理计划不能和新表单选择混用。存在 checkpoint 时才显示“继续 / 重新校对 / 完全重建”三种模式；新任务不再平铺无关的恢复选项。
- 前端日志文件名增加输出目录指纹；活动任务仍优先使用持久化 run-state 中的准确日志路径。不同输出根目录的同名任务不能互相污染状态。
- 启动器扫描范围扩展到 `8765..8799`，会优先复用 source hash 与当前代码一致的实例。它不会擅自终止仍在运行的旧实例。
- 文件名清理会移除至少两个连续出现的常见字幕语言标签，同时保留电影名中单独出现的 `English`、`French` 等正常单词。
- 服务端表单设置成为跨端口恢复的优先来源；手动字幕轨选择随当前视频路径保存，路径变化时仍会立即清空并要求重新分析，避免相同 stream index 被带到另一部电影。

## 59. 全面易用性审查后仍需继续处理的边界

以下是全面审查形成的优先级清单。P1 的前三项已经在问题 60-62 中实现；P2 的工作量估算、产物历史和设置并发部分已在问题 63-65 继续处理：

1. **系列批量队列（P1，已解决）**：见问题 60。队列、独立 worker、逐集分析、暂停/重试和进程接管均已持久化。
2. **远程隧道守护（P1，已解决）**：见问题 61。翻译进程改用独立、可重连的 loopback 桥接，不再持有前端隧道 URL。
3. **成片视听复核（P1，已解决）**：见问题 62。复核弹窗已经集中视频帧、前后音频、波形、相邻字幕和 checkpoint 编辑。
4. **复核工作量控制（P2）**：一部长片可能产生数百个阅读速度或像素候选。需要按严重度、置信度和共同根因聚类，并支持模型提出批量修复、用户抽样确认，不能要求逐条点击。
5. **时间/调用量预估（P2，已解决）**：见问题 63。页面根据字幕单元数或片长、batch size、缓存命中、断点和复核轮数给出粗略调用量与耗时范围。
6. **产物发现与任务历史（P2，已解决）**：见问题 64。页面提供受限的产物清单、打开输出目录和最近任务历史，服务端会重新解析并验证已知任务目标。
7. **前端架构和并发设置（P2，部分解决）**：见问题 65。跨进程设置锁已经完成；HTML/CSS/JS 静态资源拆分和单实例发现协议仍是后续边界。
8. **真实设备交付矩阵（P2）**：ASS、双语 SRT、字体 MKS 和 `mobile` 样式已有输出，但仍需在实际 iOS/Android 播放器上记录是否支持 ASS、字体附件、系统无障碍字号、HDR 字幕亮度和双语换行。不能只凭桌面 libass 预览声称手机自适应已经验证。

## 60. 系列任务依赖网页逐集启动，关闭页面后不能继续排队

### 现象与根因

原前端只保存一个当前 PID。即使同目录有多集视频，用户也必须逐集选择、分析、启动和等待；页面关闭后没有任务清单，也没有进程级队列所有者。简单地在浏览器内保存数组仍不可靠：刷新页面会丢失运行态，worker 崩溃后还可能在旧 `audio_to_subtitle.py` 进程仍存活时重复启动同一集。

### 修复

- 新增 `subtitle_queue.py`，把队列、暂停状态、条目 payload、处理 PID、进度、错误和 worker 心跳原子保存到 `runtime/queue/subtitle-queue.json`；跨进程文件锁防止多个前端或 worker 同时覆盖。
- “扫描同目录剧集”按自然数字顺序递归发现支持的视频文件，已在等待/运行的路径不能重复加入。网页提供全选、加入、开始、暂停领取、上移、下移、取消、重试、移除和加载复核。
- 新增独立 `subtitle_queue_worker.py`。它串行处理队列，关闭网页不影响当前集或后续集；空闲 5 分钟后可退出，下次网页或队列恢复会按需重新启动。
- 每集先重新调用来源分析，再把该集处理计划中的中文、源语言、补充和音频基准写入准备后的 payload。路径专属 sidecar 不跨集复用；同结构剧集的显式 stream 选择仍接受该集资产验证。
- worker 启动处理进程前就保存准备后的 payload；崩溃恢复时先读取输出目录 run-state 并校验 PID、进程创建时间和完整命令。旧进程仍活着就接管监控，已结束则依据日志/checkpoint/质量报告收尾；仅分析阶段退出才重新排队。
- 暂停只阻止领取下一集，不强杀当前集；运行中取消由 worker 调用既有进程树终止逻辑。失败条目保留 checkpoint，用户重试继续从最近有效批次恢复。
- 空队列时“开始队列”和“暂停领取”保持禁用；直接粘贴新视频路径会立即清空上一部影片的片名、轨道选择和旧分析，避免批量条目继承错误元数据。

### 边界

队列当前按单机单 worker 串行运行，没有跨电脑调度。加入时复制的是统一处理策略，仍应保证同一季剧集的轨道结构基本一致；特殊集应加载后单独确认来源。队列状态不保存 SSH 明文密码，远程无人值守必须使用密钥或 DPAPI 已保存密码。

## 61. SSH 隧道属于前端进程，页面退出或网络切换会中断远程翻译

### 现象与根因

问题 34 通过“每个网页实例只使用自己的随机隧道端口”避免串线，但隧道生命周期仍属于 `subtitle_frontend.py`。翻译子进程独立存活时，关闭网页就会关闭 Paramiko client；Wi-Fi/有线网络切换后 transport 失效，也没有健康检查和自动重建。夜间批量任务因此可能在模型调用中途停住，而重新打开网页并不会修复旧子进程持有的 URL。

### 修复

- 新增独立 `remote_ollama_bridge.py`。它在 `127.0.0.1:11436..11455` 暴露稳定代理，内部 SSH 转发使用随机端口；前端、单任务子进程和队列 worker 都只持有稳定代理 URL。
- `remote_bridge_manager.py` 使用跨进程启动锁发现或启动唯一可用桥接进程。Windows 使用独立进程组、隐藏窗口和文件日志，关闭前端不会终止桥接。
- 桥接从服务端设置读取 SSH config/密钥或 DPAPI 解密后的密码，连接失败按 1、2、4 秒递增到最多 30 秒持续重试；连接后每 10 秒检查远程 `/api/version`，transport 或 Ollama 失效就撤销旧转发并重建。
- 代理请求在隧道暂时不可用时等待恢复并返回明确 `503`，不会改写为本地 `127.0.0.1:11434`。页面轮询显示“已连接 / 自动重连中”，运行按钮在远程未恢复前保持锁定。
- “连接”仍先用前端临时隧道验证主机、known_hosts、认证和模型列表；保存配置后切换到独立桥接。密码未勾选 DPAPI 保存时保留当前网页连接，并明确提示关闭页面后不能恢复。
- 桥接状态文件使用线程串行化、进程/线程唯一临时文件和 Windows 短重试原子替换，避免启动线程与监控线程并发写入时偶发 `WinError 32`。

### 2026-08-01 真实验证

- 使用 SSH 密钥连接 `csynth@10.12.96.203` 成功，稳定代理位于 `127.0.0.1:11438`，可读取 6 个远程 Ollama 模型。
- 主动要求桥接重载后，重连计数从 1 增至 2，内部随机转发端口从 `14886` 更新为 `13658`，随后 `/api/tags` 仍正常返回 6 个模型。
- 该验证覆盖真实 SSH 断开重建路径，但没有切断物理网卡、VPN 或路由器，因此仍保留下面的网络环境边界。

### 边界

网络在远端已完成推理但响应尚未返回时中断，重试可能增加一次模型调用成本；批次结构校验和 checkpoint 原子写入保证结果不会重复落盘。当前没有主动“关闭桥接”按钮，桥接会保持本机 loopback 监听并等待后续任务。自动化测试覆盖首次失败后的退避重连；真实网络切换仍需在目标 SSH 网络环境中做破坏性验证，不能仅凭单元测试宣称所有路由器/VPN 场景已验证。

## 62. 成片复核只有文字表格，无法同时判断声音、画面和相邻语境

### 现象与根因

问题 49 已允许修改 checkpoint，但弹窗只有时间和双语文本。字幕过长、对白已经结束才出字、ASR 听错、片内文字遮挡等问题需要同时看目标帧、听前后音频、观察波形并比较相邻字幕；打开外部播放器再手工输入时间会显著增加复核成本，也容易改错相似 ID。

### 修复

- 新增 `review_evidence.py`，按 checkpoint ID 和旧开始时间定位唯一事件；默认截取目标前后各 4 秒、最长 14 秒的音频，在字幕中点提取真实视频帧，并由该音频生成波形。
- 证据只在打开某条复核项时生成，缓存键包含视频路径、大小、修改时间、事件时间和音轨。再次打开直接复用；修改时间或替换视频后不会错误沿用旧证据。
- 复核弹窗扩展为视听工作台：左侧显示视频帧、波形、音频控件和前后各两条字幕，右侧保留开始/结束、源文、中文和显示开关，并支持上一条/下一条待复核项。
- 媒体接口不接收任意文件路径。后端只为刚生成且已登记的文件签发随机临时 token；未知 token 返回 404。音频支持 HTTP Range，桌面和手机浏览器可以拖动播放。
- 保存仍沿用运行态拒绝、事件 ID + 旧时间乐观锁、原子 checkpoint 替换和 `manual_reviewed_at`；视听证据生成失败不会阻止用户编辑文字。
- 手机窄屏把相邻字幕从三列表格切换成“时间 / 英文 / 中文”纵向条目，避免中文逐字换行；桌面仍保留便于横向比较的三列表格。弹窗使用边框盒高度约束，在桌面和手机上都不会越出视口。

### 2026-08-01 真实验证

- 使用《21世纪性爱指南》第 1 集的现有 checkpoint 打开 18 条可定位复核项；真实视频帧为 `640×352`，波形为 `1200×180`，音频时长 14 秒且 readyState 为 4，前后共显示 5 条字幕。
- 音频 `Range: bytes=0-1023` 返回 `206 Partial Content` 和准确 `Content-Range`；切换到下一条复核项后帧、音频范围和当前字幕同步更新。
- 应用内浏览器在桌面 `1280×720` 和手机 `390×844` 下均无水平溢出；手机相邻字幕使用纵向布局，桌面弹窗保持三列表格。

### 边界

单帧不能判断完整镜头运动，短音频也不能替代逐镜口型精校。工作台解决的是“定位和证据集中”，不会自动批准同步、遮挡或译文质量；最终仍需重新运行“继续任务”生成 ASS/SRT 和质量报告。证据目录 `.review-evidence/` 属于可重建缓存，不提交 Git。

## 63. 122B 与夜间复核没有调用量和耗时提示

### 现象与根因

运行前只能看到模型名称与复核策略。选择 `qwen3.5:122b`、减小 batch 或打开两轮夜间复核后，调用量可能成倍增加，用户必须启动后才知道任务规模；新任务在字幕尚未抽取时又没有精确单元数。

### 修复

- 新增独立 `run_estimator.py`。优先使用 checkpoint/来源字幕的真实条数，缺失时按视频时长生成明确标注的粗估条数。
- 分开计算风格分析、首轮翻译/校对、术语审查、独立终审和夜间多轮复核调用；继续任务会结合兼容 checkpoint、已完成数量和终审缓存扣除可复用工作。
- 按模型体量提供宽松的单次调用耗时区间，并叠加 ASR、位图 OCR、字幕同步和最终交付处理的粗略时间。
- “运行前确认”实时显示“约 N 次调用 · 时间范围”，悬停可查看首轮、终审和夜间复核拆分。参数或运行方式改变后自动重新估算。

### 边界

估算不计网络中断重试、模型响应格式修复、低置信 OCR/ASR 的额外校正，也无法预知远程服务器排队和模型换入显存时间，因此只能用于排期。字幕尚未抽取时，按平均 3.4 秒一条得到的数量必须保持“按片长估算”标识，不能当作精确费用。

## 64. 完成后难以找到交付文件，最近任务接口又不能暴露任意路径

### 现象与根因

ASS、SRT、字体 MKS、质量报告、渲染预览和同步报告分散在较深的系列/片名目录中。原页面主要显示日志和长输出路径，没有可扫描的产物清单；若直接让前端提交系统路径给 `explorer.exe`，本地网页又会扩大到任意文件访问能力。

### 修复

- 新增 `task_artifacts.py`，只识别固定的字幕交付、报告、风格、术语、同步、渲染与镜头缓存类型；质量报告中指向任务目录外的路径会被忽略。
- 当前任务显示完整产物清单、大小、更新时间和受限的“定位”操作。服务端不采用前端提交的文件路径，而是用输出根目录、系列名、片名和固定产物键重新解析。
- “打开输出目录”要求目标中存在 checkpoint、运行状态、质量报告或已知产物；只有两层名称但内容为空的普通目录会被拒绝。
- 最近任务从真实输出目录的报告、checkpoint、ASS 和运行状态恢复，不维护可能漂移的第二份数据库。历史接口只返回状态、复核项数、产物数量、更新时间与目录上下文，加载当前任务时才返回完整清单。

### 2026-08-01 真实验证

- 在《21世纪性爱指南》现有输出根目录恢复 8 个任务；单集识别到 18 类现有产物，包括双语 ASS/SRT、字体 MKS、质量报告、渲染预览和术语人工修订。
- 去除历史列表中重复的完整产物数组后，8 集 JSON 从约 60 KB 降到约 3.6 KB；任务数量、状态和产物计数保持一致。

### 边界

历史是输出目录扫描结果，不是作业审计数据库；用户移动或删除目录后条目会随之消失。文件管理器操作只在本机 loopback 前端可用，不能作为远程 Web 文件浏览器。

## 65. 多个旧前端实例可能覆盖同一份设置

### 现象与根因

问题 40 把设置迁移到服务端原子 JSON，但“读旧值、修改一个区域、写回”仍是三个独立步骤。旧端口与新端口同时保存时，一个实例可能用较早快照覆盖另一个实例刚保存的表单或远程连接配置。

### 修复

- `FrontendSettingsStore` 为 `%LOCALAPPDATA%\BilingualSubtitlePipeline\.frontend-settings.json.lock` 增加跨进程 `FileMutex`。
- `load`、表单保存和远程配置保存都在同一锁内完成；更新操作锁住完整的“读取、合并、原子替换”过程，表单与远程配置不会因并发写入丢失。
- 锁文件只保存一个用于系统文件锁的占位字节，不包含密码或设置内容；密码仍只以当前 Windows 用户的 DPAPI 密文落盘。

### 边界

当前只解决共享设置的丢更新问题。HTML/CSS/JS 仍内嵌于 `subtitle_frontend.py`，不同源码版本的历史服务仍可同时监听不同端口；静态资源拆分、版本化 API 与单实例发现协议尚未完成。
